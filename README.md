# hos-rules — HOS direction files, Jira ticket template and spec-pack prompt

Everything an agent-built HOS repo needs to be driven from its spec pack: the Cursor and Claude Code direction files for both
code repos (with the UI click rule), the Jira ticket template with its schema, a checker and a Jira import converter, and the
`/build-pack` prompt that produces the spec folders.

```
hos-rules/
├─ rules/
│  ├─ HumanifyOS/        Go repo: AGENTS.md · CLAUDE.md · .cursor/rules (17) · .cursor/MANIFEST.md · DROPPED.md
│  │                     .claude/skills · nested CLAUDE.md per module folder · .golangci.yml · tools/arch-lint.sh · docs/ARCHITECTURE.md
│  └─ HumanifyOS-UI/     TypeScript repo: the same set, .cursor/rules (18) including 45-ui-clicks.mdc, tooling/eslint/boundaries.js
├─ jira-template/
│  ├─ README.md          the template: every field, the bar, how it renders in Jira, the import rules
│  ├─ ticket.schema.json the ticket batch schema (JSON Schema 2020-12)
│  ├─ ticket-template.json  a blank two-ticket batch (blocker + ticket) that passes the checker in --strict mode
│  └─ examples/          Q-45 (a real HOS-UI ticket): source JSON, its Jira description, its Jira import
├─ tools/
│  ├─ check_tickets.py   holds every ticket to the bar (schema, words, ACs, test command, locks, blockers, cycles, links, clicks)
│  └─ to_jira.py         ticket batch → Jira Cloud JSON import (no reporter / created / Story Points, status To Do, Blocks links)
├─ prompts/build-pack.md the /build-pack prompt: scattered design work → one validated spec pack
└─ SKILLS.md             the coding skill packs to import under these rules
```

## Install the rules into a code repo

The files in `rules/<Repo>/` belong at that repo's root, same relative paths:

```bash
cp -R rules/HumanifyOS/.    /path/to/HumanifyOS/        # Go repo
cp -R rules/HumanifyOS-UI/. /path/to/HumanifyOS-UI/     # TypeScript repo
```

`cp -R …/.` copies the dot folders (`.cursor`, `.claude`) too. In the HOS build these files are generated by
`/HOSPACK/HOS/tools/merge_repo_root.py` and installed by ticket F-09; never edit them in the repo — change the generator and
regenerate. The rules reference the pack at `HOSPACK/…` (both pack folders sit at the root of both repos).

How they load: `.cursor/rules/00-hospack-always.mdc` is the one always-on rule (it attaches `AGENTS.md`, about 7.5 KB). Program
pages `02-program-*.mdc`, the layout rule `10-backend|10-frontend`, module rules `20–24`, the click rule `45-ui-clicks` attach
by folder; topic rules `30–35` and `40-ticket` load on request. `.cursor/MANIFEST.md` lists every file, how it loads and its size.
Claude Code reads `CLAUDE.md` and the nested `CLAUDE.md` files the same way.

Cursor cloud agents only see rules and skills committed to the repo (`.cursor/rules`, `.cursor/skills`, `.claude/skills`).

## The click rule

`rules/HumanifyOS-UI/.cursor/rules/45-ui-clicks.mdc` (globs `apps/web/**`, `packages/ui/**`, `packages/features/**`): every element
whose click opens something, navigates or runs a function is a test-case requirement — one user-event test per clickable that
asserts the visible result, keyboard and disabled cases, tests never deleted or skipped to make a change pass, and a `Clickables`
list in every PR. It is a plain `.mdc` file: copy it into any front-end repo's `.cursor/rules/`.

## Tickets → Jira

```bash
python3 tools/check_tickets.py my-tickets.json --schema jira-template/ticket.schema.json --strict
python3 tools/to_jira.py my-tickets.json --name "Humanify OS" --key HOS --out JIRA_IMPORT.json
```

Then Jira Cloud → Settings → System → External system import → JSON. See `jira-template/README.md`.

## Regenerating from the pack

In the HOS pack: `bash HOSPACK/HOS/tools/regen_all.sh` (then the HOS-UI and HOS-Admin copies). The copies here were taken from the
2026-10-29 regeneration: HOS 8,581 checks, HOS-UI 4,628, HOS-Admin 3,860, 0 failures, 0 warnings; 487 tickets, 1,664 Blocks links.
