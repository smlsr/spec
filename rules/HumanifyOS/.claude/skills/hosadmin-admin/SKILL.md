# HOSPACK/HOS-Admin — adding things the HOSPACK/HOS-Admin way (AdminServer)

**HOS-Admin is the HumanifyOS administration program (AdminServer `hos-adminserver` :8150, the Admin web app `apps/web/admin`: clients/programs/LOBs, users/teams/roles/SSO, models, CARES profiles, engines console, rubric library/builder/ZTP/assignments, audit, approvals; admin roles platform_admin · tenant_admin · program_admin · rubric_admin · qa_ops).** The platform contract it builds on lives in the sibling pack `HOSPACK/HOS/` at the same repository root (LOOM, SWATCH, RUBRIC, CORE: OpenAPI, SQL, events, auth/tenancy, config keys, the base preamble `HOSPACK/HOS/LOOM/spec/CURSOR_PREAMBLE.md`, `HOSPACK/HOS/api/`, `HOSPACK/HOS/schema/`) — it is **read-only for HOS-Admin agents**: never edit `HOSPACK/HOS/**`, never add a route, table or event there, never take a HOS ticket. `HOSPACK/HOS-UI/**` (the end-user application program) is a sibling pack too — read-only here; HOS-UI consumes `/v1/admin/audit/events`, `/v1/admin/roles/effective` and the rubric-builder deep link, nothing flows the other way. HOS-Admin code lives only in apps/admin/*, internal/admin, pkg/contracts/admin (Go) and apps/web/admin, packages/ui/src/admin, packages/contracts/admin, services/mock-api admin fixtures (TS); everything else in the repository belongs to HOS or the other sibling program. HOS-Admin starts when HOS gate G-READY is green (`scripts/hos-ready.sh`: core-api, rubric-maint query API, the seed, the token minter, the bus; prerequisites in `HOSPACK/HOS-Admin/plan/hos_prerequisites.json`, contract `HOSPACK/HOS-Admin/INFRA-FROM-HOS.md`); HOS-Admin **builds on HOS (read-only)**, is **consumed by HOS-UI** (which starts at HOS-Admin gate G-RBAC: roles/RBAC + `POST /v1/admin/audit/events` live) and never depends on HOS-UI.

- Contract first: `HOSPACK/HOS-Admin/ADMIN/spec/openapi/openapi-admin.yaml` → `make codegen` → implement. Platform contracts (`HOSPACK/HOS/<MODULE>/spec/openapi/`) are read-only.
- Routes in `apps/admin/hos-adminserver/server`, domain code in `internal/admin/<pkg>`; the AdminServer is a BFF over core-api (:8110) and rubric-maint (:8130) through `pkg/lib/invoke`, never a second store for anything they own; the admin audit store `adm_audit` is append-only (Q-304); events: constants in `pkg/common/events.go` (append-only), rows in `pkg/lib/events/subscriptions.go`, handlers at `/events/<type>`.
- Tables: only `adm_*` (migrations 0030–0039, first file `0030_admin_v30.sql`, `HOSPACK/HOS-Admin/ADMIN/spec/sql/`; own DB role `admin_app`, keys `ADMIN_DATABASE_URL` / `ADMIN_DB_*`); never a table that describes an evaluation, a rubric definition, a fact or an org entity (those are CORE's, RUBRIC's, LOOM's — the AdminServer edits them through their APIs).
- Tests: one named test per acceptance criterion; `go test ./apps/admin/... ./internal/admin/...`, `make admin-e2e` (compose), `scripts/admin-live-smoke.sh` (live).
- Readiness: a HOSPACK/HOS-Admin ticket that needs the platform running starts only when `scripts/hos-ready.sh` is green (HOS gate G-READY: core-api, rubric-maint, seed, tokens, bus).
