## Workflow — autonomous, parallel, no check-ins

One of many parallel agents; nobody reads the chat: no plan approval, no "shall I proceed". Decide, build, prove, open the PR.

1. **Plan**: beyond a trivial change, checkable items in `tasks/todo/<ID>.md` (yours alone), then go; pull your spec root and the ticket's links first. Sideways: stop, re-plan there; never push a failing approach, never ask.
2. **Subagents** for research, logs, parallel analysis; one task each, inside your lock units.
3. **Verify before done**: AC tests pass, lint/boundary green, behaviour diffed against `main` where it matters, logs checked; evidence a Staff engineer would approve in `RESULT.json`; tick the todo file, end it with a review.
4. **Elegance, balanced**: redo hacky non-trivial fixes; never over-engineer simple ones.
5. **Fix bugs autonomously**: failing test, red CI, log line: root cause, no temporary patch.
6. **Lessons**: after a correction, pattern + rule in `tasks/lessons/<ID>.md`; read `tasks/lessons/README.md` first; only `scripts/gate-close.sh` (`make lessons-sweep`, P-11) consolidates; never edit the README or another ticket's lesson.
7. **Simplicity, minimal impact**: smallest correct change, no bugs elsewhere.
8. **Docs in the same PR**: `docs/technical/<module>/<area>.md` (Mermaid for flows over two steps) and `docs/user/<app>/<area>.md` (a screenshot per UI change, captured by the tests into `docs/user/screens/<route>.png`); a behaviour change without both is incomplete.

## Definition of done (every ticket)

Tests named after every acceptance criterion green · lint and boundary checks green · `tasks/todo/<ID>.md` ticked with a review section · `docs/technical/<module>/<area>.md` and `docs/user/<app>/<area>.md` updated in the same PR (screenshot for every UI change under `docs/user/screens/`, Mermaid diagram for any flow with more than two steps) · `tasks/lessons/<ID>.md` written if anything corrected you · `RESULT.json` in the PR body. No check-ins, no plan approval: you are one of many parallel agents and nobody is reading the chat — decide, build, prove, open the PR.
